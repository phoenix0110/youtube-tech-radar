# B 站适配度评分规则（科技赛道）

## 一、五维软指标（LLM 打分，0-10 分）

| 维度 | key | 定义 | 打分锚点 |
|------|-----|------|----------|
| 信息密度 | `density` | 单位时间可提取的知识/观点/数据量 | 10=每分钟都有硬核知识点（拆解/基准/源码级）；6=有干货但节奏偏慢；3=聊天闲扯为主；1=纯广告/预告 |
| 视觉表现 | `visual` | 画面质感/演示效果/动画/实物展示 | 10=电影级+可视化动画/实物拆机/精致实验；6=PPT+屏录+人脸；3=纯屏录无剪辑；1=PPT念稿 |
| 中文受众基础 | `cn_base` | 该频道/话题在 B 站已有的认知度和热度 | 10=B站已有大量搬运且播放量高（MKBHD/3B1B级）；6=有零星搬运；3=全新频道无中文内容；1=纯小语种/极小众 |
| 叙事适配 | `narrative` | 画面驱动 vs 口播驱动，二创改造难度 | 10=画面自解释、弱口播（拆机/实验/可视化）；7=口播但故事线清晰易配中文解说；4=依赖英语梗/代码逐行讲解；1=纯对谈/播客 |
| 爆点强度 | `explosion` | 标题党潜力：冲突/反差/悬念/争议，B 站标题能不能炸 | 10=天然爆点（首发评测/重大漏洞/行业地震/翻车/挑战）；5=平稳专业内容；1=平淡教程无悬念 |

## 二、总评公式

```
total = 0.20*density + 0.20*visual + 0.15*cn_base + 0.15*narrative + 0.30*explosion
```

再加两个硬分微调（脚本算）：
- **热度增速**：view_count / (days_old + 1)。周内 >80 万/天 为顶级热点，排名前 20% 加 0.3 分
- **时长适配**：8–25 分钟最适配 B 站（+0.2）；<4 分钟偏短（0）；>40 分钟偏长（-0.1）

## 三、人群映射（每视频标 1–2 个主适配人群）

| 人群 | 画像 | 选题偏好 | 时长 | 内容形态 |
|------|------|----------|------|----------|
| **S. 学生/入门向** | 18–25，大学生/自学转码 | 编程入门/科普短片/考证备考/AI入门 | ≤20min | 结构清晰、易懂、有代入感 |
| **D. 数码控** | 20–35，关注硬件更新 | 手机评测/笔电对比/开箱/性价比 | ≤20min | 画面驱动、产品实物、数据对比 |
| **G. 极客/开发者** | 22–35，有编程/运维经验 | 底层技术/安全/工具链/开源 | 10–35min | 实操演示、代码走读、技术深度 |
| **K. 知识向** | 25–40，泛知识消费 | 深度科普/纪录片/技术经济学/科学可视化 | 15–40min | 叙事强、视觉优美、"原来如此"型 |
| **C. 职场向** | 25–40，关注职业竞争力 | AI工具/效率提升/行业趋势/科技新闻 | ≤20min | 实用导向、能学到能用上 |

**类型 → 人群速查**：
- 消费电子评测(1) → D / C
- AI·机器学习(2) → C / G / S
- 编程开发(3) → S / G
- 科普·科学(4) → K / S
- 科技新闻(5) → C / D
- 极客·网络安全(6) → G / S

## 四、打分输出格式（scores.json）

LLM 读 `videos_raw.json` 后写 `scores.json`：

```json
[
  {
    "video_id": "xxxx",
    "density": 8, "visual": 7, "cn_base": 9, "narrative": 8, "explosion": 9,
    "audiences": ["D", "C"],
    "reason": "一句话：这个选题的爆点是什么，为什么 B 站用户会点",
    "bili_title_hint": "如果二创，标题可以往哪个方向打"
  }
]
```

打分依据：标题 + 频道背景（references 里 6 类频道的已知风格）+ 简介。信息不足时保守打 5 分，不臆造。
